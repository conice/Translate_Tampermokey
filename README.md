# Translate Tampermokey

Tampermonkey 用户脚本:选中网页上的词 → 浮窗显示翻译 → 一键收藏进生词本 → 生词本里的词在该站点的页面上以「原文(译文)」形式常驻。

## 安装

```bash
npm install          # 只为测试,运行时不依赖任何包
npm run build        # 生成 dist/translate-tampermokey.user.js
```

把 `dist/translate-tampermokey.user.js` 拖进浏览器,或打开 Tampermonkey 面板 → 添加新脚本 → 粘贴内容。

## 使用

| 操作 | 位置 |
| --- | --- |
| 取词(桌面) | 双击任意网页上的词,默认开启 |
| 取词(手机) | 长按选中词或一段话(可跨行,≤400 字符)→ 点选区旁浮出的 44px「译」圆钮;滚动时圆钮跟着选区走 |
| 加入生词本 | 浮窗里的按钮(超过 5 个词或 40 字符时不可收藏) |
| 查句子 | 选中一句话(≤400 字符)后双击;译文保留大小写与分段,不请求词典、不可收藏 |
| 复制译文 | 浮窗里的「复制译文」,词条和句子都有;站点拒绝剪贴板时按钮不变、不报错 |
| 超限提示 | 选区超过 400 字符时,选区旁短暂显示「最多 400 字」(桌面与触屏都会) |
| 发音 | 浮窗里的 🔊,有词典录音就播录音(优先美音),没有或用不了则用系统 TTS;录音播放中再点一次停止 |
| 深色模式 | 默认跟随系统,可在面板「设置」里强制浅色/深色 |
| 打开生词本 / 设置 | Tampermonkey 菜单 →「打开生词本 / 设置」 |
| 生词本展开分组 | 每个语言分组默认只列最新添加的 3 个词;点分组名(标题)展开全部,再点一次收起;搜索时直接列出全部命中项 |
| 本站注音开关 | Tampermonkey 菜单 →「开启/关闭本站注音」,或面板「设置」页 |
| 本站目标语言 | 释义浮窗右下角的下拉框;选「自动」则按页面语言判断,改完立即按新目标重新查询 |
| 默认词典 | 面板「设置」页;有道 / 微软 / 欧陆 / 英英,决定每次新查询从哪个词典取释义 |
| 临时换词典 | 释义浮窗右上角的一排词典 logo(有道红、微软四色、欧陆蓝、英英灰),点一下换当前这个词的释义,不改默认设置 |
| 导出 / 导入 | 面板「设置」页:导出打开保存对话框存成 CSV;导入先选文件,再选「覆盖现有」或「合并」 |

> 导出的文件是 UTF-8 CSV(带 BOM),列依次为 `term,normalized,sourceLang,targetLang,translation,phonetic,partOfSpeech,addedAt`。列顺序可以调换;`sourceLang`、`targetLang`、`translation` 必填,`term` 与 `normalized` 至少给一个,缺这些值的行会被跳过。以 `=`、`+`、`-`、`@` 开头的单元格在导出时会加一个 `'` 前缀,免得 Excel 把网页上抄来的文字当公式执行;导入时这个前缀会被去掉,手工编辑时也可以照同样规则写。`entryId` 不写进文件,导入时按 `sourceLang|normalized` 重新算出,手改 CSV 不会把词条身份改乱。导入时「覆盖现有」会清空当前生词本(文件解析、表头校验通过、且至少有一行可用之后才清空;拿错文件、空文件、内容全坏的文件都不会清空),「合并」保留现有词条并更新同名词条(见 `docs/adr/0008`)。

> 手机上不要试「双击」:Chrome for Android 只有关掉双击缩放才会派发 `dblclick`,iOS Safari 从不派发。看到「译」圆钮就说明触屏路径已生效(`docs/adr/0006`)。选区为什么能到 400 字符、为什么允许跨行,见 `docs/adr/0007`。

## 设计要点

- **目标语言**:页面主语言非中文 → 译成中文;是中文 → 译成英文;可在释义浮窗里按站点改(见 `GLOSSARY.md`)。
- **生词本按语言自动分组**:每条词条归入它自身语言(源语言)的组,组名右侧是条数,组内按收藏时间倒序;组的先后固定,不会因为今天新存了一个词就整组上移。语言名与浮窗的目标语言图标共用一张表,同一门语言在两处叫法一致。
- **分组默认折叠到最新 3 个**:几百个词不该一次糊满整屏,而刚存的词最可能被再看一眼;组名就是一个按钮(带箭头与 `aria-expanded`),点开显示全部、再点收起,展开状态在删除词条和切换标签后保持不变。搜索时分组强制展开,免得把刚搜到的行藏起来。展开的是分组本身,不是整本书,所以别的语言仍保持收起。
- **触屏与桌面走不同入口**:触屏端选词后浮出「译」气泡再点一下才查询,桌面端直接双击;两者共用同一条查询流程与同一个释义浮窗(`docs/adr/0006`)。气泡在滚动时跟着选区走,选区完全滚出视口才收起;桌面端滚动不关浮窗。
- **注音默认关闭、按站点开启**:它要改写宿主页面的文本节点,是最容易把页面弄坏的部分(`docs/adr/0003`)。
- **注音只匹配生词本里的词**:不做整页双语对照(`docs/adr/0004`)。
- **注音跟随所在文字的颜色**:用 `currentColor` 加透明度,而不是固定灰,所以深色正文、彩色标题上都能读;关键样式带 `!important`,免得被站点全局样式盖掉。
- **清理注音不碰整页文本节点**:每个标记换回它自己包住的那段原文,只有父节点全是文本节点时才在该父节点上合并;不调用整页的 `document.normalize()`,免得把 React/Vue 依赖的节点身份合并掉。
- **词与句子共用一条查询流程**:超过词条上限(40 字符或 5 个词)的选区按句子处理,只翻译、不请求词典、不可收藏,译文保留大小写与分段。
- **三处浮层共用一套主题变量**:默认跟随系统深色模式,可在面板强制浅色/深色;变量以自定义属性写在各自的 Shadow 宿主上,站点的 CSS 进不来。
- **发音优先真人录音**:词典源给出音频就播它(按文件名优先美音),下载、解码、`Audio` 构造任一步失败都静默回退系统 TTS,不弹错误。
- **词典源与翻译源分开**:译文和释义是两条独立的路,释义拿不到只降级为「暂无释义」,不影响译文;默认用有道(唯一返回 JSON 的中文向词典),微软与欧陆抓页面,页面改版只会让释义消失(`docs/adr/0010`)。
- **释义浮窗的两处开关各占一角**:右上角是词典 logo 一行(有道红、微软四色方块、欧陆蓝、英英灰),当前源全亮并加描边,其余半透明;它标注「仅本次」,只影响当前这个词。右下角是目标语言下拉框,和收藏、复制放在同一行。音标、词性、发音、复制与收藏也都带图标,配色全部来自主题变量,深色下同样成立。
- **默认词典与临时词典**:设置页决定每次新查询的起点,浮窗里的切换标注「仅本次」,只服务于当前这个词;词典缓存的 key 含词典源,换源不会串答案。
- **翻译源为有序失败转移**:`clients5 → mymemory → lingva`,全部免费、全部**不保证稳定**(`docs/adr/0002`)。
- **所有请求走 `GM_xmlhttpRequest`**:绕过页面 CSP 与 CORS(`docs/adr/0001`)。
- **缓存 key 不含 provider**:换源不会让已看过的译文失效(`docs/adr/0005`)。
- **本机存储也是 CSV**:生词本、设置、翻译缓存三个 GM 存储键都存成 CSV 文本,与导出文件共用一套解析器;旧版留下的 JSON 值仍能读,下次写入自动转换(`docs/adr/0009`)。

## 验证

```bash
npm test             # 单元 + DOM + 打包产物冒烟
npm run build        # 版本号取自 package.json
```

覆盖三层:

1. **纯逻辑**(`core/`):归一化(词形与句子两条路径)、语言判定、主题判定与解析、缓存 TTL/LRU、provider 解析与选音、三个词典解析器(有道 JSON、必应与欧陆页面)、释义截断与实体解码、词形、匹配器、触屏手势判定与可见性判定。
2. **DOM**(jsdom):注音层的幂等、跳过 code/contenteditable、嵌套容器不重复处理、`refresh` 能还原原文、样式对关键属性带 `!important` 且只注入一次、清理只合并自己的父节点;浮窗的词条与句子两种形态、复制失败不报错、右上角词典 logo(位置、logo 标记、选中态、临时切换)、右下角目标语言下拉框(位置、默认值、改选)、加载与空错误状态、设置页默认词典的回显与保存;生词本分组的折叠(默认 3 个、点标题展开、再点收起、搜索时全展开、展开状态跨删除保留);超限提示的 2 秒消失。
3. **打包产物冒烟**(jsdom + 打桩的 `GM_xmlhttpRequest`):启动、版本号与 `package.json` 一致、双击查询、收藏、失败转移、全挂时的错误态、菜单开关、缓存去重、句子模式(无词典请求、无收藏按钮)、复制、超限提示、主题切换、默认词典决定新查询的源、浮窗换词典重新请求且不写回设置,以及触屏分支(打桩 `matchMedia` 后选词出气泡、点气泡查询、取消选区收回气泡、44px 尺寸、滚动跟随与滚出视口收起、跨行选区出气泡、窄屏浮窗布局、桌面滚动不关浮窗)。导出/导入与存储格式另有独立用例:CSV 转义、列序、BOM、坏行统计、覆盖与合并、旧 JSON 值的读取与自动改写。

### 真机手测清单

这些在 Node 里**跑不到**,因为 jsdom 没有真实的选区、布局与媒体栈。每发一版前在真机上逐条过一遍:

- [ ] **触屏取词**:长按选中一个英文词 → 出现「译」圆钮 → 点它出浮窗 → 收藏 → 菜单里开启本站注音后该词右侧出现译文。
- [ ] **气泡大小与滚动**:圆钮明显好点(44px);上下滚动时圆钮跟着选区走,而不是停在原地或直接消失;把选区滚出屏幕后它才收起。
- [ ] **跨行选区**:拖选一段跨两三行的英文(400 字符内)→ 同样出圆钮,点它得到分段的译文。
- [ ] **超限提示**:选一段超过 400 字符的文字 → 选区旁出现「最多 400 字」,约 2 秒后消失。
- [ ] **句子模式**:选中一段带换行的英文 → 双击 → 译文仍分两行、首字母没有变小写、浮窗里没有「加入生词本」;点「复制译文」能粘贴出同样分段的文字。
- [ ] **深色模式**:系统切到深色后,浮窗、译气泡、面板三处都变深色,在白底站点上不刺眼;面板里强制「浅色」后立刻变回浅色;再切回「跟随系统」。
- [ ] **发音(含 iOS)**:查一个常见英文词(如 `run`)→ 点浮窗里的 🔊 → 听到的是录音而不是机器音;再点一次能停;换一个没有录音的词仍能听到机器音。iOS Safari 上另外确认点 🔊 后确实出声(自动播放策略最常在这条上拦人)。
- [ ] **注音可读性**:在一个深色主题站点和一篇浅色正文的站点上各开启一次本站注音,注音应跟随正文颜色(白字处偏亮、黑字处偏暗),而不是固定灰;关闭后页面文字与开启前一致。
- [ ] **本站目标语言**:查一个词 → 用浮窗右下角的下拉框切到「日语」→ 译文按新目标重新查询,该站点此后的查询都保持日语;刷新页面后仍然有效;切回「自动」后恢复按页面语言判断。
- [ ] **默认词典**:面板「设置」把释义词典改成「微软词典」→ 刷新页面后再查 `run`,浮窗右上角微软四色方块高亮,并显示微软的释义与音标;面板里的选择在刷新后仍保留。
- [ ] **临时换词典**:点浮窗右上角的欧陆 logo → 释义与音标随即换成欧陆的结果,该 logo 高亮、其余变淡;关掉浮窗再查另一个词,仍从面板设置的默认词典开始;设置页与 Tampermonkey 存储里的默认值没有被改写。
- [ ] **浮窗排版**:窄屏(手机)上词典 logo 不压在关闭按钮下面、目标语言下拉框仍在最右下角;深色模式下 logo 本身保持品牌色,其余控件跟随主题。
- [ ] **词典失效降级**:断网或让词典域名不可达后查词 → 译文仍正常显示,浮窗只多一行「释义加载失败」或「该词典暂无释义」,收藏与发音不受影响。
- [ ] **生词本分组**:在不同语言的页面各存一个词(如英文页的 `run`、日文页的 `猫`)→ 面板「生词本」出现「英语」「日语」两个组,组名右侧条数正确;搜索只留命中词条时,空组随之消失。
- [ ] **分组折叠**:在同一个语言下存 5 个以上词 → 该组默认只显示最新 3 个、标题旁有箭头、条数是总数 → 点组名展开全部,箭头转向;再点一次收起 → 展开后删一个词,组仍保持展开 → 在搜索框里输入能匹配到第 4 个以后的词,该词直接可见。
- [ ] **导出文件**:面板「设置」→「导出到文件」→ 出现保存对话框,默认文件名是 `生词本-YYYY-MM-DD.csv`;保存后用 Excel 或文本编辑器打开,中文不乱码、每行一个词条;取消对话框时面板显示「已取消导出」而不是「已导出」。
- [ ] **导入 · 覆盖**:先保存一份导出文件,再删掉几个词条,然后「从文件导入」选它 → 选「覆盖现有」→ 生词本恢复成文件里的内容,`addedAt`(添加时间)保留原值。
- [ ] **导入 · 合并**:在已有生词本上导入一份包含重叠词条的文件 → 选「合并」→ 原有词条仍在,重叠词条的译文被文件里的值更新,添加时间保持原值。
- [ ] **导入的坏文件**:随便选一个非 CSV 文件(如 `.txt`)→ 面板显示「导入失败」并说明缺哪一列,生词本不变;选一个只有表头的 CSV 并点「覆盖现有」→ 提示「文件里没有可导入的词条」,生词本不被清空。
- [ ] **旧数据迁移**:从 0.3.x 升级后打开已装页面 → 生词本与设置原样保留;改一次主题或加一个词 → 在 Tampermonkey 存储里看到 `settings` / `entries` 已经是 CSV 文本(而不是一行 JSON)。

## 已知限制

- 免费翻译源随时可能失效或封 IP,`clients5` 是 Google 未公开的内部接口。
- `lingva.ml` 的公共实例在 2026-10-26 的实测中只回显原文而不翻译;它排在 MyMemory 之后,主要作为自建实例的接口。
- 词典信息(音标、释义)只支持英文单词;中文词条只有译文,句子也没有音标与释义(句子本就不查词典)。非英文词不会出现词典图标行。
- 微软与欧陆词典没有公开的 JSON 接口,脚本解析的是它们的网页;有道用的是未公开的 `jsonapi`。任一页面结构或接口参数变化,都可能让该词典突然「暂无释义」——这只影响释义,译文、发音回退与生词本不受影响(`docs/adr/0010`)。
- 宿主站点重渲染可能抹掉注音,MutationObserver 会重放,但不保证覆盖所有框架的写法。
- 注音样式虽然带 `!important`,但同权重下后加载者赢:极少数站点用更高优先级的选择器加 `!important`,或直接给元素写内联样式,仍可能改掉注音的字号或颜色。
- 关闭注音时,如果被注音的段落里还嵌着别的元素(`<b>`、`<a>` 等),脚本不会合并该段落的文本节点 —— 这是刻意的,合并会动到框架持有的节点。此时页面文字与开启前一致,只是文本被分成几个相邻的文本节点。
- 浮层的深色模式跟随**系统**与面板设置,不读取宿主页面自己的主题;在页面自带的深色皮肤上选了「浅色」,浮层就是浅色。
- 触屏端依赖浏览器派发 `selectionchange` / `touchend`;极少数内嵌浏览器的自定义选区可能不派发。
- 无云同步;换设备靠面板里的 CSV 导入/导出。旧版导出的 JSON 文件不能再导入。
- 导出优先用 `showSaveFilePicker`(真正的「另存为」对话框),但只有 Chromium 系且页面是安全上下文(`https`)时才有;其余情况(含 Firefox、手机浏览器、用户脚本沙箱里拿不到该 API)自动退回浏览器下载,文件内容一样,只是没有选路径的对话框。
- 导入依赖原生文件选择框;在极少数内嵌浏览器里,取消选择可能不触发 `cancel` 事件,此时面板不会报错,再点一次「从文件导入」即可。
- 存储改为 CSV 后**不能回退到 0.3.x**:旧版读到 CSV 会当作空,生词本显示为空(数据仍在,装回新版即恢复)。升级本身无需准备,0.3.x 的 JSON 值会在新版首次读取时自动迁移;若打算回退,先用 0.4.x 导出一份 CSV —— 0.3.x 只有 JSON 文本导出,那个文件不能当 CSV 导入(`docs/adr/0009`)。

## 目录

```
src/core/   纯逻辑,无 DOM(含共用的 CSV 读写与词典解析)
src/app/    查询流程、发音播放、剪贴板、文件导入导出与 GM 存储适配
src/ui/     浮窗、译气泡、提示条、面板、注音层、主题色板
docs/adr/   每个"为什么这么做"的决策记录
build.mjs   零依赖打包器(把 ESM 子集内联成一个 userscript)
```

本仓库的挂载点不支持符号链接,npm 无法安装 esbuild 之类的打包器,所以 `build.mjs` 自己做了拓扑内联。它只支持本仓库用到的语法子集(具名相对导入 + `export` 声明),遇到之外写法会直接报错而不是产出坏包。

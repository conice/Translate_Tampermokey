# 下一版(0.3.0):P0 五项

Status: ready-for-agent

## Problem Statement

用户装好脚本后,在真实使用里会撞上五类问题:

1. **夜间没法学。** 释义浮窗、面板、译气泡全是硬编码白底黑字。系统切到深色后,这三块在深色页面上像一块贴在脸上的白纸。注音用的是固定灰 `#6b7280`,在深色页面和浅色字体的标题上几乎看不见。
2. **发音只有机器人。** 词典源已经解析出真人音频地址,但查询流程把它丢掉了,浮窗只有系统 TTS。对正在学发音的人来说,机器音的价值有限。
3. **句子查不了。** `normalizeTerm` 对每次查询都转小写、抹平换行,于是查一句话得到的译文是一串没有大小写、没有分段的文本;超过 40 字符时浮窗又只给一句「过长,仅可查看」——像在报错。超过 400 字符则完全没有任何反应,用户以为脚本坏了。
4. **触屏取词很脆。** 译气泡只有 40px,低于常用触控下限;滚一下页面气泡就消失,得重新选词;选区超过 120 字符或含换行时干脆不出气泡,手机上拖选一段话查不了。
5. **注音可能被站点样式盖掉,且清理时可能改坏宿主页。** 注音样式注入宿主 `<head>`,与站点 CSS 同源同权重,后加载者赢;刷新注音时调用全页 `document.normalize()`,会合并整页文本节点,而 React/Vue 依赖节点身份。

## Solution

一次性发布 0.3.0,让脚本在夜间、在手机上、在读长句时都可用:

- 三处浮层共用一套 CSS 变量,默认跟随系统深色模式,并可在面板里强制浅色/深色。注音改用宿主文字颜色加透明度,在任何底色上都可读。
- 有真人音频就播真人音频(优先美音),取不到或被页面 CSP 挡住时静默回退系统 TTS,按钮仍然只有一个。
- 句子作为正常结果呈现:保留大小写与换行,只给译文、复制、发音和关闭;不请求词典、不显示收藏区。超过 400 字符时给一句可见提示,不再静默。
- 译气泡涨到 44px、随滚动重定位、选区上限放宽到 400 字符并允许跨行。
- 注音的关键样式加 `!important` 保持不被站点覆盖;刷新注音时只清理自己产生的标记,绝不调用全页 `document.normalize()`。

## User Stories

1. 作为夜间阅读的用户,我希望释义浮窗跟随系统深色模式,这样晚上查词不会被一块白底晃眼。
2. 作为不喜欢自动跟随的用户,我希望能在面板里强制浅色或深色,这样浮窗的外观由我决定而不是由系统决定。
3. 作为色觉/对比度敏感的用户,我希望深色模式下的次要文字(音标、检测语言、提示)仍有足够对比度,而不是灰到看不见。
4. 作为触屏用户,我希望译气泡和面板在深色模式下同样变暗,这样它们看起来像同一个产品。
5. 作为读英文的用户,我希望注音的颜色跟随所在文字的颜色,这样在深色正文、彩色小标题、白字黑底站点上都读得出来。
6. 作为装了站点自定义主题的用户,我希望注音不被站点的全局样式改掉字号或颜色,这样注音在任何站点都保持同一副样子。
7. 作为把注音临时关掉的用户,我希望关掉后页面完全恢复原文,不留下多余的文本节点或空标签。
8. 作为用 React/Vue 站点的用户,我希望开关注音不会让页面内容错位或丢失,因为脚本不会合并整页的文本节点。
9. 作为学发音的用户,我希望浮窗的发音按钮优先播放真人录音,这样我能听到真实语调。
10. 作为同一单词有多个口音录音的用户,我希望优先播放美音,没有美音时用英音或其他可用录音。
11. 作为在弱网或离线环境的用户,我希望真人音频取不到时自动用系统 TTS,而不是弹一个错误。
12. 作为只想听一下的用户,我希望在播放中再点按钮能停止播放,而不是叠着播。
13. 作为查句子的用户,我希望查询一句英文时译文保留大小写和分段,这样它读起来还是一句话。
14. 作为查句子的用户,我希望句子结果区没有「加入生词本」和词典释义,因为句子不是词条。
15. 作为查句子的用户,我希望能把译文一键复制走,这样能直接贴到别处。
16. 作为查单词的用户,我希望单词结果也能复制译文,因为复制是同一个动作。
17. 作为不小心选了整页的用户,我希望看到一句「最多 400 字」,而不是什么都没发生。
18. 作为触屏用户,我希望能拖选一段话(含换行)后出译气泡,这样手机上也能查句子。
19. 作为触屏用户,我希望气泡足够大,不用瞄准也能点中。
20. 作为触屏用户,我希望滚动页面时气泡跟着选区走,而不是直接消失,这样我不用重新选词。
21. 作为触屏用户,我希望滚动时浮窗自动关闭,这样它不会在窄屏上一直遮住内容。
22. 作为桌面用户,我希望滚动页面时浮窗保持打开,这样我能在看译文的同时滚动回上下文。
23. 作为桌面用户,我希望浮窗不随滚动移动,因为它锚定的是我选中时的位置。
24. 作为安装者,我希望 userscript 头里的版本号和 `package.json` 一致,这样我知道自己装的是哪一版。
25. 作为后来维护者,我希望触屏取词边界的变化记在 ADR 里,这样下一个改这里的人知道为什么是 400 字而不是 120。

## Implementation Decisions

**主题**

- 新增设置项 `theme`,取值 `system`(默认) / `light` / `dark`,存进现有 settings 存储键。
- 每个 Shadow DOM 宿主(`:host`)定义一组 CSS 变量:`--tm-bg`、`--tm-fg`、`--tm-muted`、`--tm-border`、`--tm-accent`,以及深色下的对应值。变量定义在 `:host` 与 `:host(.theme-dark)` 上,由脚本在宿主元素上加类,而不是靠 `@media` 在 shadow 内部自动生效——三处浮层需要一致的判定,且设置项可能强制覆盖。
- 生效判定是纯函数:输入 `{ themeSetting, prefersDark }`,输出 `'light' | 'dark'`。`prefersDark` 由 `matchMedia('(prefers-color-scheme: dark)')` 提供;系统偏好变化时(监听该媒体查询的 `change`)重新应用,不需要刷新页面。
- 不做页面背景亮度探测。浮层是浮层,不是页面的一部分。
- 注入宿主 `<head>` 的注音样式不进这套变量:注音颜色改为 `currentColor` 加透明度(带回退),字号、边距仍显式设定。

**注音**

- 注音样式的关键属性(字号、颜色、左右边距、`white-space`、`user-select`、`cursor`)全部加 `!important`,类名不变。
- 刷新注音时只遍历自己产生的标记元素,把每个标记换回其原始文本节点;只有当该父节点的子节点**全部**是文本节点时才调用该父节点的 `normalize()`,否则不动。移除对 `document.normalize()` 的调用。
- 每个标记元素记录其原始文本(现有实现取首个文本子节点,已满足),保证换回时是原文而不是注音后的拼接。

**发音**

- 词典解析结果里的 `audio` 继续保留在解析产物中;查询流程把它传给浮窗。
- 选音是纯函数:在 `phonetics[]` 中按 URL 文件名含 `-us`、`-uk`、否则任一非空 `audio` 的顺序挑一个;返回 `undefined` 表示没有录音。
- 新增一个可注入的 `fetchBlob(url)` 依赖,与现有 `fetchText` 并列,内部用 `GM_xmlhttpRequest` 的 `responseType: 'blob'`。音频与词典接口同域,`@connect` 名单不需要新增条目。
- 播放流程:点按钮 → 若正在播则停止 → 有录音则取 blob、`URL.createObjectURL` 播放、结束或出错时 revoke → 取 blob 或播放失败则静默回退现有 `speak()` 系统 TTS。
- 音频地址不写进词条。等面板发音那一版再一起加字段。
- blob 与 object URL 都需要可注入/可打桩(jsdom 没有媒体播放能力),但浮窗不应直接依赖全局 `URL`,通过注入的播放器接口调用。

**长文本 / 句子模式**

- 新增一条「整理文本」的路径,与现有归一化并列:只折叠内部空白、去首尾空白、保留大小写与换行。归一化(转小写、去标点)继续只用于词条身份。
- 查询流程按 `canBecomeEntry`(≤40 字符且 ≤5 词)判定词条模式还是句子模式;句子模式不请求词典、不算原形、不显示收藏区。
- 查询上限保持 400 字符。超过时不再静默:在选区旁浮出一句短暂提示,复用现有的放置函数,2 秒后自动消失。
- 浮窗新增「复制译文」,词条模式与句子模式都有。写入剪贴板失败时不报错(剪贴板权限在部分站点被拒是常态)。

**译气泡与触屏取词**

- 气泡可见尺寸 44×44,圆角与字号同比微调。
- 气泡新增 `update(rect)`;`main.js` 的滚动监听按 rAF 节流地取当前选区矩形并调用它,锚点完全离开视口时才隐藏。
- 触屏取词上限从 120 字符放宽到 400 字符,并允许含换行的选区(句子模式承接)。桌面双击路径的上限不变。
- 触屏端滚动时关闭释义浮窗;桌面端滚动时浮窗保持打开且不移动。

**发布**

- 版本统一为 0.3.0(userscript 头与 `package.json`)。
- 新增 ADR-0007,记录触屏取词上限与跨行选区的放宽,以及它相对 ADR-0006 的增量。其余四项只进 commit 与 README。

## Testing Decisions

- 只测外部行为:选中什么 → 浮窗显示什么、点按钮后发出什么请求、开关之后 DOM 长什么样。不测内部函数调用顺序,不断言私有字段。
- 纯逻辑走现有 `core/` 测试风格(无 DOM,直接断言返回值):主题判定纯函数、选音纯函数、文本整理路径、触屏取词判定。
- DOM 行为走现有 `test/gloss-layer.dom.test.mjs` 的 jsdom 风格:注音样式含 `!important`、刷新后只清理自有标记、父节点含元素子节点时不被合并。
- 端到端走现有打包产物冒烟测试(`test/userscript.smoke.test.mjs`),它已经打桩了 `GM_xmlhttpRequest`、`matchMedia`、`getBoundingClientRect`。新增覆盖:
  - 深色:打桩 `matchMedia` 返回深色,断言宿主元素带深色类;切换设置后断言类变化。
  - 发音:打桩的词典响应里带 `audio`,断言请求打到音频地址;不带 `audio` 时断言没有音频请求。
  - 句子模式:41 字符选区断言只有译文、复制、发音、关闭,没有收藏按钮,且没有词典请求;超 400 字符断言提示出现。
  - 气泡:44px 尺寸;滚动后气泡的定位被更新而不是被隐藏;选区跨行且 400 字符内出气泡。
- 每个 ticket 先写红测再实现。jsdom 无法验证的部分(真实音频解码、iOS 上 blob 播放、真实滚动惯性)写进 README 的手测清单。

## Out of Scope

- 键盘可达性与焦点管理(浮窗 `role="dialog"` 但仍无焦点陷阱、气泡不可键盘触发)推迟到 P1。
- 面板的排序、标签、批量删除、翻译源状态页、历史记录、Anki 导出。
- 桌面端新增取词入口(Alt+点击、选完自动出气泡)。
- 词条新增 `audio` 字段及其展示。
- 云同步。
- 修复 `disabledProviders` 这个死设置(与主题无关,单独一轮)。
- 面板在 iOS 上 `max-height` 被地址栏裁掉的 `dvh` 修正——留给面板那一版一起做。

## Further Notes

- 免费翻译源随时可能失效,本次不改动失败转移链,也不改缓存策略。ADR-0002、ADR-0005 不受影响。
- ADR-0003(注音按站点开启)与 ADR-0004(注音只匹配生词本)不受影响;本轮只改注音的样式隔离与清理方式,不改何时开启、匹配什么。
- ADR-0006 的桌面/触屏分工不变,只是触屏这一侧的取词上限和翻滚行为放宽。
- 真机手测清单在实现完成后补进 README:触屏滚动跟随、深色模式在三个浮层上的观感、iOS 上点发音按钮能出声、长按选跨行段落能出气泡。

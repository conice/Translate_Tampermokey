# 01: 主题变量与深色模式

**What to build:** 系统处于深色模式时,释义浮窗、译气泡、面板三处浮层一起变暗,次要文字(音标、检测语言、提示)仍保持可读对比度;面板里能强制「浅色」或「深色」,选择被记住;系统偏好改变时三处浮层即时跟随,不需要刷新页面。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 新增设置项 `theme`,取值 `system`(默认)/ `light` / `dark`,存进现有设置存储,面板设置页有对应控件
- [ ] 主题判定是纯函数,输入设置值与系统是否深色,输出 `light` / `dark`;该函数有单元测试覆盖三种设置值 × 两种系统偏好
- [ ] 三处浮层的宿主共享同一组颜色变量名(背景、前景、次要文字、边框、主色),深色值由脚本在宿主上加类切换,而不是靠 `@media` 在阴影内自动生效
- [ ] 释义浮窗、译气泡、面板在深色下都使用深色变量,不存在某处仍然是白底
- [ ] 深色下次要文字与背景的对比度足够,不出现「灰到看不见」的情况
- [ ] 系统偏好变化时(媒体查询的 `change` 事件)三处浮层即时切换,不要求刷新页面
- [ ] 面板切换主题后立即生效,重启后保持
- [ ] 注入宿主 `<head>` 的注音样式不参与这套颜色变量(注音的可读性由 04 单独处理)
- [ ] 打包产物冒烟测试覆盖:打桩深色系统偏好 → 宿主带深色类;切换设置 → 类随之变化

## Comments

**实现说明(与 spec 的一处偏离)**:spec 写的是「在宿主上加类,`:host(.theme-dark)` 定义深色值」。实现改为把变量**内联写在宿主 `style` 上**,不做类切换。理由:类方案要把同一份色值同时写进 JS 与 CSS 两处,二者会漂移;内联变量让色值只有一份,且「用户强制主题」与「系统主题」走同一条路径。行为等价 —— 一处判定、三处浮层同时生效。若日后要支持第三方主题注入,再改回类方案。

**测试的边界**:jsdom 既不解析 `var()` 也不解析 shadow 内的自定义属性,所以「实际绘制的颜色」在测试里不可观测。测试用两个代理量共同锁定行为:①调色板确实写到了宿主;②每个浮层的样式表确实读取了对应变量。真机观感仍需手测。

**审查后修正**:`.pos` 与面板目标语言输入框两处残留硬编码颜色改为变量(前者浅色下曾从 4.69:1 降到 3.05:1,低于 12px 文本的 4.5:1 下限);面板的主题选项改为复用 `THEMES`,不再复制一份取值清单;`main.js` 的媒体查询监听补上旧版 Safari 的 `addListener` 回退,并修正 matchMedia 缺失时的缓存逻辑;纯函数测试补全为 3 设置 x 2 偏好的全部 6 种组合。

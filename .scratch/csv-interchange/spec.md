# CSV 交换与本机存储

Status: ready-for-agent

## Problem Statement

生词本与外部之间原来只有一种往来方式:面板里一整块 JSON 文本框,复制出去、粘贴回来。它有三个问题:

1. **人读不了,也改不了。** 换设备时用户只能整块复制;想改一个译法要数括号。这份数据的自然归宿是表格(Excel、Sheets、Anki 导入),而 JSON 不是表格。
2. **没有文件。** 导出不能存成文件,导入不能从文件选,全靠剪贴板在浏览器和别的工具之间搬运。
3. **本机存储是一行几百 KB 的 JSON。** 在 Tampermonkey 的存储查看器里没法确认「这个站点为什么开了注音」「生词本到底存了什么」,出问题时只能读代码。

## Solution

- 生词本与外部交换用 CSV(RFC 4180,UTF-8 带 BOM,首行表头)。
- 导出打开系统保存对话框(`showSaveFilePicker`),不可用时退回下载;导入用系统文件选择框,读到文件后再问「覆盖现有」还是「合并」。
- 三个 GM 存储键(生词本、设置、缓存)也改为 CSV 文本,与导出文件共用同一个解析器。
- 旧版留下的 JSON 值仍能读,下次写入自动变成 CSV。

## User Stories

1. 作为换设备的用户,我希望把生词本存成一个 CSV 文件,这样我能用网盘、邮件或 U 盘带走它。
2. 作为会改数据的用户,我希望用 Excel 打开生词本、改一行译文再存回去,这样我不必手写 JSON。
3. 作为谨慎的用户,我希望导入前先看到「现有 N 条」,并自己选择覆盖还是合并,这样我不会误删生词本。
4. 作为升级的用户,我希望已有的生词本和设置原样保留,这样我不需要做任何迁移操作。
5. 作为排查问题的用户,我希望在存储里看到的是按行排列的设置和词条,这样我能一眼看出某个站点为什么开了注音。

## Acceptance

- 导入一个只有表头的文件并选「覆盖现有」时,现有生词本保持不动。
- 导入任何文件之前,生词本不变。
- 0.3.x 写下的 JSON 存储值可被读取,且下一次写入变成 CSV。
- `npm test` 全绿;构建产物在 jsdom 里启动无报错。
- 真机清单(README)逐条通过。

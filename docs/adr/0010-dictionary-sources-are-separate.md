# 词典源与翻译源分开,默认有道

释义(音标、词性、词义)来自**词典源**(Dictionary Source),与**翻译源**(Provider)是两条独立的路:

- 翻译是查询的主体,失败要重试、要失败转移;释义是附加信息,拿不到也不能让整个查询失败。所以词典请求单独包在 try/catch 里,任何解析异常都降级为「该词典暂无释义」,译文照常显示。
- 每个词典解析器遇到不认识的页面结构时返回 `undefined`,而不是抛错或猜。页面改版的结果应该是「没有释义」,不是「查询失败」。

现有五个源,前四个服务英文,`krdict` 是后来为韩语补的:

| id | 名称 | 语言 | 取法 |
| --- | --- | --- | --- |
| `youdao` | 有道词典 | en | 未公开的 `dict.youdao.com/jsonapi` JSON 接口 |
| `microsoft` | 微软词典 | en | 抓取 `cn.bing.com/dict/search` 页面里的 `qdef` 块 |
| `eudic` | 欧陆词典 | en | 抓取 `dict.eudic.net/dicts/en/<word>` 页面里的 `#ExpFCchild` |
| `dictionaryapi` | 英英词典 | en | 原有的 `api.dictionaryapi.dev` |
| `krdict` | 韩国语学习词典 | ko | 抓取国立国语院 `krdict.korean.go.kr/chn/dicMarinerSearch` 的中文检索页 |

**默认有道**。三个中文向词典里只有它返回结构化 JSON,音标、发音、词性都不需要解析页面标记,页面改版的风险最低;有道的 `dicts` 参数还能把 `run` 的应答从 ~500 KB 压到 ~2 KB。微软、欧陆与 krdict 没有公开 JSON 接口,只能抓 HTML —— 这也是已知限制,页面结构一变就可能突然没有释义。

**词典源声明语言,查询按语言选源**。每个源带一个 `lang`,只有与词的源语言一致才会被请求。默认词典只在它服务这种语言时生效:英文词从四个英文源里按设置挑一个,韩语词自动走 `krdict`,没有对应源的词(法语、德语……)根本不发词典请求。理由有两条:一是把 `사과` 发给有道只会拿回空页,白花一次请求;二是把韩语源设成全局默认会让所有英文词失去释义,所以设置里只列英文源,韩语不必设置。

**只有一本词典的语言不渲染切换行**。浮窗右上角的 logo 排是「换一本看看」,只有一本时它变成一个不能产生结果的按钮,所以韩语词只显示释义、不显示那一排。`changeDictionary` 仍然只服务当前这一次查询;缓存 key 含源 id 与源语言,`dict|krdict|ko|사과`,换源不会串答案。

**默认词典是设置,浮窗里的切换只是「仅本次」**。设置页决定每一次新查询从哪个源开始;在释义浮窗里换源只影响当前这个词,不写设置。理由和「本站目标语言」不同:目标语言是长期阅读偏好,词典则是这一次想对照哪本,没必要污染全局。

浮窗里两个开关各占一角:词典用各家的 logo 排在右上角(紧挨着被解释的词),目标语言仍是右下角的下拉框(紧挨着它改变结果的收藏/复制)。词典用 logo 是因为四本英文词典一眼可辨,而且切换是单次动作;语言用下拉框是因为它有九项、且选中的是一个长期设置,文字比字形更不容易认错。logo 全部用内联 SVG 或带品牌色的字符块绘制,不加载任何远程图片:页面 CSP 不一定允许远程图片,加载失败还会让一排按钮变成空白。

**缓存 key 含词典源与源语言**:`dict|<id>|<lang>|<word>`。这与 0005「翻译缓存不含 provider」刻意相反 —— 两个翻译源给出的是同一句话,可以互换;两本词典给出的是各自的释义与音标,互换会让用户以为切换没生效,也会让一本词典的答案覆盖另一本的缓存。语言同样要进 key:`dict|krdict|ko|사과` 与任何英文源的结果没有可比性。缓存的仍是解析后的结果,不是原始页面。

几个取舍:

- **没有词典源的语言不发请求**。四个英文源都是英汉/英英词典,韩语只有 krdict;中文、法语、德语等暂时没有源,句子也从不查词典。浮窗在这种情况下不出现词典下拉框或 logo 行。
- **韩语词典按原形检索**。krdict 不收 `먹었어요`、`갔어요` 这类活用形,查询会返回「该词典暂无释义」;这是词典本身的收录范围,不做词形还原去猜。
- **krdict 的检索结果是「包含该词」而不只是词条本身**,`사과` 会一并列出 `사과나무`、`사과하다`,所以解析时必须拿 `<dl>` 里的词头与原词精确比对,否则会把派生词当成义项。
- **每个词性最多三组释义,每组最多约 100 字**。词典页会为一个 `run` 列出十几条释义,浮窗的原意是「扫一眼」,不是替代词典;超出部分整条释义保留并用 `…` 截断,不切在半句中间。
- **发音优先美音**。有道取 `usspeech`,必应取 `#bigaud_us`,欧陆取页面上第二个音标(英式在前、美式在后),krdict 取 `fnSoundPlay('…')` 指向的录音(krdicmedia 域名)。没有录音时照旧回退系统 TTS。
- **新增的域名要写进 `@connect`**。`dict.youdao.com`、`cn.bing.com`、`dict.eudic.net`、`krdict.korean.go.kr`、`krdicmedia.korean.go.kr` 都已加入,否则 Tampermonkey 会拦截请求。

代价:微软、欧陆与 krdict 的解析依赖页面标记,没有稳定契约;有道的 JSON 接口同样未公开,`dicts` 参数随时可能被改。这几种失效都只影响释义,不影响翻译与生词本。

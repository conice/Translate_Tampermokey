# 触屏端用「译气泡」,桌面端保留双击

双击在手机上不是一个可用的入口:Chrome for Android 只有在关闭双击缩放时才派发 `dblclick`,iOS Safari 从不派发。用户装完脚本在手机上「双击英文词」没有任何反应,所以触摸设备需要另一条路径。

选定的做法是:检测到主输入为手指(`pointer: coarse`,回退到 `maxTouchPoints` / `ontouchstart`)时,监听原生选区的稳定状态,在选区旁浮出一个「译」圆钮,点它才发起查询。长按选词是手机用户本来就会的复制手势,因此不要求学新动作;而「选完必须再点一下」也正好把复制和查询分开,不会在只是想复制时误触发请求。

桌面端不发气泡,继续用双击;两者共用同一条查询流程与同一个释义浮窗,浮窗在触屏上改为窄屏全宽布局并带显式关闭按钮。

代价是触屏端每次查询都要多点一下。被拒的替代方案:①统一改成「选完自动查」——复制文本也会发请求,且无法取消;②触屏端也监听 `dblclick`——iOS 上根本等不到;③自己识别双击时间间隔——与浏览器原生的双指缩放、长按菜单冲突,且各浏览器行为不一致。

`selectionchange` 在拖动选区手柄时会持续触发,所以判定要防抖;判定本身放在 `core/gesture.js` 的纯函数里,因为 jsdom 不派发 `selectionchange`,`touch` 分支只能通过纯函数与打桩的 `matchMedia` 在测试里覆盖。
